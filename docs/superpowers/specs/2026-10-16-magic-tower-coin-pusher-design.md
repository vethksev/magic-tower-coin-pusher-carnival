## 1. 機台與物理

> **2026-10-16 改版：機台改為真 3D。** 以下 1.1–1.5 係 2D 頂視版嘅規格，保留作歷史；實際採用 1.6 嘅 3D 規格。數值系統（第 2 節起）唔受影響，因為 `Machine` 對外只發同一組信號。

### 1.6 3D 機台（現行）

- **結構**（經典雙層街機推幣機）：
  - 下層平台：寬 20 單位（1 單位＝1 幣直徑）、深由推板前面到前緣 z=6；前緣跌落＝塔門（計分）。
  - 推板：長方體，闊 20、深 8、高 1.2，喺平台後方沿 z 正弦來回（行程 4、週期 2.4 秒）。推板頂面就係「上層架」。
  - 固定刮板：喺推板後半上方嘅固定牆（z ≤ −4，y 由推板頂起）。推板後退時，頂面上嘅幣被刮板擋住、相對推板向前移，最後由推板前緣跌落到下層平台，再被下一次推進推入床幣。
  - 側牆：x=±10 全長。前段（z>3）平台只有 |x|≤9，兩側係邊坑，被推出界嘅幣跌落＝流失。
- **幣**：`RigidBody3D` + `CylinderShape3D`（半徑 0.5、厚 0.12），重力 400 單位／秒²（＝9.8 m/s² 換算 1 單位 2.4 cm），摩擦 0.35、彈性 0.05。用 Jolt 物理引擎（Godot 4.7 內建）。
- **發幣**：A／D 左右槽。幣由推板頂面左／右邊緣以 y=頂面+0.06 橫向滑行（無碰撞、凍結），撞到幣或對面牆先「落地」變物理體；如果當刻推板已後退，落地點喺推板前面就直接跌落下層平台。
- **床幣**：下層平台預鋪一層六角密鋪銅幣（x ∈ [−9.2, 9.2]、z 由推板最前位置+0.6 到 5.5），約 130 枚；3D 堆疊由物理自然產生。
- **攝影機**：透視，喺機台前上方（約 (0, 14, 17) 望向 (0, 0.5, −1)，fov 30°），似 RACCOIN 嘅正前微俯視。
- **分區判定**：幣 y < −1 即離開平台：z > 5 → 計分（塔門）；否則 → 流失（邊坑）。
- **像素感**：3D 喺 640×360 渲染、整數放大，唔另加後處理；材質用平色低粗糙度，光源一盞方向光＋環境光。
- 信號、靜止判定（彈匣空後 2 個推板週期無跌落）、seed、`MachineTuning` 集中調參：同 2D 版一樣。

### 1.1 版面（2D 舊版，已棄用）

- 機台區 400×300 邏輯像素，置中偏左；右邊 240 像素闊嘅側欄放勇者狀態、怪物卡、彈匣。
- 機台由後到前分三區：
  - 後台（推板滑行區）深 110 像素。左右兩角各一條發幣槽。
  - 前台（靜止平台）深 130 像素。
  - 前緣跌落帶高 20 像素＝「塔門」。幣跌入即計分／造成傷害。
- 左右邊坑各闊 18 像素，只喺最前 50 像素（y 230–280）。幣跌入坑＝流失，無分無效果。邊坑係風險來源；道具「石護欄」可以封一邊或兩邊。（Phase 0 實測：邊坑貫穿成個前台會令流失多過跌落，所以縮短。）

### 1.2 幣物理

- 每枚幣係 `RigidBody2D` 圓形碰撞體，頂視圖碟仔。直徑：銅幣 14、銀／金幣 16、特殊幣 18 像素。
- 枱面摩擦用 linear damp 3.0 模擬；物理材質摩擦 0.6、彈性 0.1。
- 單層平面，幣唔疊（2D 冇真正堆疊）。堆疊感由功能幣（磁石、地震、聖水）同 combo 事件補返。
- 跌落判定：幣中心過前緣線 → 停物理、播 0.3 秒跌落動畫 → 發 `coin_scored(coin)` 信號。過邊坑線 → 播流失動畫 → 發 `coin_lost(coin)`。

### 1.3 推板

- `AnimatableBody2D`，正弦來回推動。週期 2.4 秒，行程 36 像素。
- 推板每完成一個週期發 `pusher_cycle` 信號。**推板週期係全遊戲節奏單位**：怪物反擊、停留型幣效果都按「推一下」計。

### 1.4 發幣

- 左右槽喺後台兩角。A／D 鍵或者撳槽發幣；空格雙發。長按連發，冷卻 0.25 秒。
- RACCOIN 式：左槽幣向右滑、右槽幣向左滑（300 像素／秒），沿推板前嘅條帶橫向滑行，**撞到幣或對面牆先落地**；兩邊齊發會喺中間相撞成堆。滑行期間無碰撞、y 每 tick 貼住推板前沿 + 半徑 + 2，保證唔會被推板包入身體。落地一刻先開碰撞變物理幣，帶少量向前速度；落點 y 有 ±2 像素 seed 抖動。
- 每層開局彈匣 20 枚銅幣，再加入玩家喺商店買嘅特殊幣（彈匣順序隨機但按 seed 可重現）。

### 1.4a 床幣（機台預載）

- 真推幣機嘅平台一開始就鋪滿幣，推一下先會有幣跌。所以每層開局機台預鋪一層「床幣」：全部係銅幣（值 1），**六角密鋪**（中心距 14.2、行距 12.3），由 y=88.5 到 273（16 行，最後一行邊緣剛貼跌落線 280）；後台行（y<230）鋪到牆邊、前台行只鋪到邊坑線（x 25–375），約 410 枚。Phase 0 實測：稀疏方格床（行距 17）會將推力全部吸收，零跌落；密鋪而且左右無空隙先會「入一枚、跌一枚」。
- 推板前沿最遠去到 y=76，所以推板直接掂到嘅係落地帶（y 47–83）；發出嘅幣落喺落地帶，推板再將佔推入床幣，連鎖推前，前排床幣先跌落。實測 20 枚約跌 18–25、流失 2–3。
- 床幣跌落照計傷害同金幣（佈係玩家嘅攻擊資源）；流入邊坑照流失。
- 床幣數量、間距、起始行都喺 `MachineTuning`，手感調整時一齊調。壞幣（第 3 節）由怪物放落床幣入面，取代原位嘅銅幣。

### 1.5 確定性與調參

- 固定 60Hz physics tick。每場 run 一個 seed，所有隨機（彈匣順序、商店貨架、壞幣位置）都由 seed 派生。
- 所有手感參數集中喺 `game/machine/machine_tuning.tres`（`MachineTuning` resource）：推板週期、行程、damp、發幣滑速、冷卻、落點抖動、靜止週期數、床幣間距／範圍。調手感唔使改 code。
- Godot 2D 物理跨 run 唔保證逐位元一致（RID／島序影響求解次序），同 seed 跌落數會差 ±1；床幣初始位置同發幣抖動則完全由 seed 決定。測試只驗後者同「結果相近」。
- 唔可以對幣開 CCD（`continuous_cd`）：400 枚相貼幣會爆炸飛走。

## 2. 魔塔數值系統

### 2.1 勇者

- 開局 HP 1000、ATK 10、DEF 10、金幣 0、黃／藍／紅鑰匙各 0。
- 數值跨層持續。HP 歸零即 run 結束（戰死）。
- 層間唔自動回血；回血靠血瓶幣同商人。

### 2.2 守關怪與層目標

- 每層一隻守關怪，有 HP、ATK、DEF。層目標＝怪 HP 歸零。
- 傷害公式：每枚跌入塔門嘅幣造成 `max(1, 幣值 × 勇者ATK − 怪DEF)`。
- 反擊公式：推板每完成一個週期，怪攻擊一次，勇者扣 `max(0, 怪ATK − 勇者DEF)`。發幣越慢、結算拖越長，食嘅傷害越多——呢個係魔塔「戰鬥回合數」嘅物理版。
- 怪 HP 歸零即刻停反擊；機台上剩餘幣繼續結算，跌落嘅變金幣。

## 5. 回合與商店流程

1. **進層**：顯示怪物卡（名／HP／ATK／DEF／手冊有就顯示反擊傷害）；按規則放壞幣喺前台；彈匣填 20 銅幣＋已買特殊幣。
2. **戰鬥**：發幣、推板推、幣跌落扣怪 HP、推板週期怪反擊。怪 HP 歸零即停反擊，剩餘幣繼續結算變金幣。
3. **停滯**：彈匣空 + 機台靜止仍未殺怪 → 進入停滯處理（詳見 5.2）。
4. **勝利結算**：每枚跌入塔門嘅幣值 × 1 金幣，加層獎勵（層數 × 10 金幣）。
5. **商人**：3 格特殊幣（隨機，按 seed）、2 格道具、1 格升級（ATK +1／DEF +1／HP +100，每買一次加價）。有藍鑰匙可開第 4 格高級貨架（高級幣／裝備）。重擲一次 10 金幣。
6. **寶箱**：有黃鑰匙即開，隨機 1 件道具或 3 枚特殊幣。
7. **下層**。第 10 層魔王死 → 通關畫面 + 統計（總傷害、最大單幣傷害、用幣數）。
- MVP 冇跨 run 解鎖，冇中途存檔（run 一氣過，約 15–25 分鐘）。

### 5.1 一層內嘅狀態

| 狀態 | 進入條件 | 可以做嘅嘢 | 怪反擊 |
|---|---|---|---|
| 戰鬥中 | 進層後 | 發幣、用消耗品 | 每推板週期 1 次 |
| 結算中 | 彈匣空，機台仍有幣移動 | 用消耗品 | 繼續 |
| 停滯 | 彈匣空 + 機台靜止（見 5.4 靜止判定）+ 怪未死 | 買幣／搖台／消耗品／撤退 | 繼續 |
| 勝利結算 | 怪 HP ≤ 0 | 無（自動） | 停止 |
| 戰死 | 勇者 HP ≤ 0 | 無 | 停止 |

- 推板由進層到離層一直郁，任何狀態都唔暫停（包括停滯面板打開時）。停滯要快決定，係壓力來源。
- 時間上嘅暫停只有 Esc 系統選單（真暫停，物理同反擊都停）。

### 5.2 停滯處理

進入停滯即彈出面板，列出可用行動同下次反擊倒數：

| 行動 | 鍵 | 條件 | 效果 |
|---|---|---|---|
| 買銅幣 | B | 金幣 ≥ 5 | 扣 5 金幣，彈匣 +5 銅幣，返回戰鬥中。可重複，無上限 |
| 搖台 | S | 當層搖台次數 > 0（預設 1，風之羽毛 +1） | 機台所有幣加隨機衝量（120–200 像素／秒，方向 60% 偏前、40% 隨機），有幣可能入邊坑。之後返回結算中；若再靜止而怪未死，再入停滯 |
| 用消耗品 | 撳 icon | 有該消耗品 | 按道具效果（地震卷軸最有用）；之後返回結算中 |
| 撤退 | R | 任何時候 | 主動結束 run，死因記「撤退」，入戰死畫面。用嚟避免等死 |

- 停滯期間怪照反擊，骷髅幣照扣血。面板上顯示「下次反擊 −N HP，X.X 秒」。
- 買幣後發出嘅幣可以再觸發幣效果（分裂、火球等），照正常規則。

### 5.3 死亡條件

1. **HP ≤ 0 即戰死**，唔理係邊個狀態：反擊、骷髅幣扣血都計。
2. **進攻耗盡（僵局保險）**：喺停滯狀態下，同時滿足「金幣 < 5」「搖台 0 次」「冇可用消耗品」→ 顯示「無法再攻擊」。之後：
   - 若怪反擊傷害 > 0：等怪打死（每週期 2.4 秒扣一次）；玩家可按 R 撤退加速。
   - 若怪反擊傷害 = 0（勇者 DEF ≥ 怪 ATK）而且冇骷髅幣：永遠唔會死，所以**連續 3 個推板週期無幣跌落**即自動結束 run，死因記「進攻耗盡」。呢個計數喺任何停滯狀態都生效，避免無限等。
3. 撤退（5.2）。

### 5.4 靜止判定與卡幣保險

- 靜止＝彈匣空、無幣滑行中、而且連續 2 個推板週期（4.8 秒）無任何幣跌落或流失。唔用速度閾值：落地帶嘅等待行每個週期都會被推板推動，速度永遠唔會歸零。
- 呢個定義自動涵蓋「幣卡喺縫」同物理抖動嘅情況，唔需要另外嘅硬上限。

### 5.5 同一刻勝負與結算順序

每個 physics tick 結算順序固定：**① 幣跌落傷害 → ② 幣效果 → ③ 怪死判定 → ④ 反擊（若到週期）→ ⑤ 勇者死判定**。

- 最後一幣殺怪同時反擊令 HP 歸零：③ 先判怪死，④ 取消 → 勇者勝。
- 怪死即刻：停反擊、停壞幣所有停留效果（壞幣留喺機台變普通障礙，跌落照畀 2 金幣）、盾幣剩餘次數清零、幸運幣倍率清零、冰凍剩餘週期清零。
- 怪死後機台上嘅幣繼續結算 10 秒或直至靜止（取先者），跌落全部變金幣，然後入商人。

### 5.6 第 10 層兩場（冇紅鑰匙）

- 門衛死後**唔回血、冇商店**，機台上嘅幣保留，彈匣補 10 枚銅幣（唔係 20），停滯搖台次數重置為 1。
- 門衛死到魔王出場之間有 3 秒怪物卡過場，推板照郁但魔王未反擊。
- 魔王死＝通關。門衛階段戰死，統計層數記「10（門衛）」。

### 5.7 戰死畫面

- 顯示：去到第幾層、邊隻怪、死因（反擊／骷髅幣／撤退／進攻耗盡）、本局統計（總傷害、最大單幣傷害、用幣數、金幣總收入、時間）。
- 按鈕：再嚟一局（新 seed）／同 seed 再嚟（練習用）／返主選單。
- 死亡動畫 1.5 秒內可撳任何鍵跳過。

### 5.8 其他失敗相關規則

- 飛行器跳層：當層唔結算金幣，壞幣唔放，直接入下層怪物卡；魔王層（第 10 層）唔可用。
- 流失入邊坑嘅幣唔計傷害、唔計金幣，但壞幣入坑會消除（唔畀金幣）。
- 盾幣只擋怪反擊，唔擋骷髅幣扣血。
- 冰凍卷軸期間停滯計數（5.3 第 2 點嘅 3 週期）照計。

      pusher.gd
      machine_tuning.tres    # 手感參數

      items/*.tres           # ItemDef
      monsters/*.tres        # MonsterDef
    ui/
      hud.tscn               # 勇者欄、怪物卡、彈匣、反擊倒數
      shop_panel.tscn

    save/

  tests/                     # headless --script，一律 -- --qa

- **單向依賴**：`machine` 只發信號，唔 import `rules`；`rules` 聽信號改數值，完全唔 import Node，可以 headless 跑成千次模擬做平衡；`ui` 只讀 `run_state` 同聽信號。
- `coin_effects.gd` 對物理嘅操作（爆炸、吸引、推開）經 `machine.gd` 公開嘅少量方法（`apply_impulse_radius`、`push_all_forward`、`spawn_coin_at`、`set_damp_radius`）做，唔直接碰 RigidBody。

## 10. 風險與對策

- 物理隨機 vs 魔塔確定數值會打架 → 反擊按推板週期而非時間，玩家可以計；怪物手冊顯示倒數。
- 2D 幣唔疊，少咗真推幣機嘅堆積壓迫感 → 用磁石／地震／聖水／火球補推力感；真 3D 留 Phase 3 評估。
- 幣效果觸發時機混亂 → 第 3 節逐款標明時機，`CoinDef.trigger` 枚舉只有三個值。
- Codex 美術同 Claude 程式撞檔 → 美術只入 `assets/`＋registry JSON，程式只入 `game/`、`tests/`；詳見 `CONTRIBUTING.md`。
